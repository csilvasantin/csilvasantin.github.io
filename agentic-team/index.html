Distributed Agent Architecture

Agentic Team

Proyecto base para operar un equipo distribuido de agentes con roles claros en distintos ordenadores de una misma red.

Orchestrator central Harvey · Director General Bohr · Director Tecnico Locke · Director de Marketing

Objetivo

Construir un sistema donde varios agentes colaboren como un equipo ejecutivo real, con responsabilidades separadas y una sintesis final centralizada.

  • El Orchestrator recibe una mision.
  • Divide la tarea por rol.
  • Envia subtareas a cada agente remoto.
  • Recoge respuestas estructuradas.
  • Genera una sintesis ejecutiva final.

Despliegue

  • Ordenador 1: Orchestrator + Harvey
  • Ordenador 2: Bohr
  • Ordenador 3: Locke

Cada maquina expone una API HTTP con identidad fija y parametros minimos como AGENT_NAME, AGENT_ROLE, PORT y MODEL.

Roles

Harvey

  • Prioriza objetivos y resuelve conflictos entre areas.
  • Unifica la salida final y traduce resultados en decisiones.

Bohr

  • Evalua viabilidad tecnica, arquitectura y roadmap.
  • Detecta deuda, riesgos y prioridades de ingenieria.

Locke

  • Define posicionamiento, audiencia y propuesta de valor.
  • Propone lanzamiento, mensajes y crecimiento.

API minima

GET /health

Comprueba si el agente esta disponible.

POST /task

Entrega una tarea a un agente con su contexto y expectativas.

{
  "task_id": "abc-123",
  "goal": "Evaluar una idea SaaS para restaurantes",
  "role": "director_tecnico",
  "instructions": "Analiza viabilidad, arquitectura inicial y riesgos",
  "context": {
    "product": "SaaS para reservas y fidelizacion",
    "market": "restaurantes pequenos en Espana"
  }
}
{
  "task_id": "abc-123",
  "agent": "Bohr",
  "role": "director_tecnico",
  "status": "completed",
  "summary": "Proyecto viable con un MVP acotado",
  "details": [
    "Backend y panel web suficientes para el inicio",
    "Riesgo principal en integraciones externas",
    "Mejor evitar app nativa en la fase 1"
  ]
}

Roadmap

Fase 1

  • Contrato JSON comun.
  • Endpoints health y task.
  • Orquestacion local por red privada.

Fase 2

  • Seguimiento de estados por task_id.
  • Logs estructurados.
  • Reintentos y timeouts.

Fase 3

  • Memoria por agente.
  • Priorizacion automatica.
  • Dashboard de observabilidad.
