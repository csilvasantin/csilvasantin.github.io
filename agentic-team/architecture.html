Arquitectura de Agentic Team

Volver al resumen

Vision

Agentic Team convierte varios ordenadores de una red local en un equipo de agentes con funciones ejecutivas separadas.

  • Harvey: coordina y decide.
  • Bohr: analiza y recomienda desde tecnica.
  • Locke: analiza y recomienda desde negocio y marketing.

Principios

  • Un rol por maquina siempre que sea posible.
  • Comunicacion simple por HTTP y JSON.
  • Mensajes estructurados en vez de texto libre.
  • Orquestacion centralizada para reducir complejidad operativa.
  • Identidad fija por agente para que el equipo sea entendible.

Componentes

1. Orchestrator

  • Recibir objetivos del usuario.
  • Descomponer una mision en tareas por rol.
  • Enviar trabajo a cada agente.
  • Esperar o consultar resultados.
  • Unificar una salida final.

Funciones recomendadas:

  • Tabla de agentes registrados.
  • Asignacion por rol.
  • Trazabilidad por task_id.
  • Manejo de timeout y errores de red.

2. Agentes remotos

Cada agente remoto corre en un ordenador distinto y expone una API ligera.

AGENT_NAME=Bohr
AGENT_ROLE=director_tecnico
PORT=8001
MODEL=gpt-5.4-mini

Flujo operativo

  1. El usuario envia una mision al Orchestrator.
  2. El Orchestrator genera un task_id.
  3. Divide la mision por especialidad.
  4. Envia una peticion POST /task a cada agente.
  5. Cada agente produce una respuesta estructurada.
  6. El Orchestrator consolida las respuestas.
  7. Harvey o la capa ejecutiva publica una conclusion final.

Contratos JSON

Entrada

{
  "task_id": "launch-001",
  "goal": "Definir el lanzamiento de un SaaS B2B",
  "role": "director_marketing",
  "instructions": "Propon posicionamiento, canales y secuencia de lanzamiento",
  "context": {
    "target": "pymes de servicios",
    "region": "Espana",
    "budget": "bajo"
  }
}

Salida

{
  "task_id": "launch-001",
  "agent": "Locke",
  "role": "director_marketing",
  "status": "completed",
  "summary": "Lanzamiento inicial apoyado en outreach y contenido experto",
  "details": [
    "Definir nicho primero",
    "Crear mensaje corto y claro",
    "Validar con entrevistas y outreach manual"
  ]
}

Topologia recomendada

Opcion base

  • PC 1: Orchestrator + Harvey
  • PC 2: Bohr
  • PC 3: Locke

Opcion ampliada

  • PC 1: Orchestrator
  • PC 2: Harvey
  • PC 3: Bohr
  • PC 4: Locke

Riesgos y mitigaciones

Ambiguedad de rol

  • Incluir role e instructions en cada tarea.
  • Mantener prompts base estables por agente.

Respuestas demasiado libres

  • Exigir JSON de salida.
  • Validar esquema antes de consolidar resultados.

Caida de un nodo

  • Endpoint GET /health.
  • Timeout por agente.
  • Reintentos limitados.

Complejidad prematura

  • Empezar solo con HTTP y JSON.
  • Evitar colas, memoria persistente y paneles al inicio.

Implementacion recomendada

  • Python
  • FastAPI
  • Uvicorn
  • Pydantic

Stack pensado para prototipar rapido, validar contratos y desplegar facilmente en varios ordenadores.
